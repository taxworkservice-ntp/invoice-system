## Key Architectural Decisions (continuing)

1. **Classic V2 template**: Full copy of `PrintDocumentClassic.tsx` → `PrintDocumentClassicV2.tsx`. Admin-gated via `client_features` row. Column changes only in the items table.
2. **DN expansion on invoices**: `InvoiceFromDeliveryNotesForm.tsx` now expands each DN's line items as individual rows instead of a single summary row. Header rows per DN group show sequential numbers, sub-items have no number.
3. **html2canvas + borders**: Must use individual `<td>` cells (not `colSpan`) for header rows — `colSpan` causes border rendering bugs in html2canvas.
4. **Safari**: Final working config uses `base:'/'`, `build.target`, `modulePreload:false`, `cssCodeSplit:false`, `crossorigin` on script tag, `esbuild.target:safari15`, `<base href="/">`.
5. **CommaInput**: Custom component in `deals/new.tsx` — formats numbers with commas on blur, raw on focus. Uses `inputMode:decimal` for mobile keyboard.
6. **Partial payment flow**: Source doc status computed from `sum(all_receipt_amounts) >= net_payable`.`receipt_invoices.paid_amount` stores actual proportional allocation per invoice. `getCompletedAt` guards ALL return paths with `!isPartial`.
7. **Two copies of deal classification**: `home.tsx` (helpers used by `deriveDashboardDeal`) and `useDeals.ts` (hook used by home page ACTIVE section table). Both must be kept in sync.
8. **WHT sheet data pipeline**: Uses raw `docs` array (not `paidThisPeriod`) to include receipts for VAT businesses that `isRecognizedSalesDocument` excludes. Separate `Transaction[]` array stored as `whtTransactions` in the hook.
9. **Customer deal history stages**: Computed from ALL documents in a deal, not just the latest. Priority: overdue > partial > has_billing_note_sent > has_sent_invoice > all_paid > waiting.
