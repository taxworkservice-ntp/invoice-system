## P1 Launch Risks

### P1-1: Remaining create-path coverage and stock transaction boundary

`src/app/(client)/deals/new.tsx:1157-1317`

Creation is performed as separate deal, document, line-item, billing-link, and stock operations. The catch block attempts cleanup, but cleanup errors are ignored. A network failure or database error during compensation can leave an orphaned deal/document or an incorrect stock state.

The main new line-item creation path now uses `create_deal_document`, but billing-note creation, draft editing, and post-create stock deduction remain separate paths. Test those paths and move stock deduction into the same RPC/transaction before unrestricted launch if stock consistency is mandatory.

### P1-2: Verify transactional conversion and stock boundary

`src/app/(client)/deals/[id].tsx:343-459`

Quotation insert, line-item copy, and quotation status transition now run in `convert_quotation_to_invoice`, protected by `uq_documents_active_invoice_per_quotation`. Stock deduction still runs immediately after the RPC and is compensated on failure; verify this in staging and consider moving it into the RPC for full atomicity.

Required before unrestricted launch: apply the migration, test two concurrent conversions, and verify stock failure compensation.

### P1-3: Cron secret must be configured and verified in deployment

`api/cron/overdue.js:4-17`

The endpoint now requires `Authorization: Bearer $CRON_SECRET`.

Required before launch: configure the same `CRON_SECRET` in Vercel and verify valid cron requests succeed while missing/wrong secrets return `401`.

## P2/P3 Risks

### P2-1: Print visual regression is unverified

The automated print test cannot launch Chromium locally. PDF output, Thai font rendering, original/copy order, long descriptions, and multi-page documents still require a CI/staging browser run.

### P2-2: Storage image proxy privacy boundary is implicit

`api/storage/[action].js:133-160`

`image-proxy` does not require a bearer token. It validates the storage key and returns a signed object, apparently to support browser/PDF rendering. Confirm that storage keys are not guessable and that this endpoint is acceptable for cross-origin access before launch. Add an authenticated or short-lived access mechanism if private assets must not be retrievable by key.

### P2-3: Admin client creation has no full rollback

`api/admin/clients/create.js:33-71`

If profile, membership, or client-profile creation fails after the auth user is created, the handler does not remove the partially created user. Test and add cleanup or move provisioning into a transaction/RPC.

### P3-1: Large-list performance is unverified

Documents, deals, and catalog hooks fetch full collections without pagination. Load-test at least 5,000 documents and 10,000 catalog items before launch or set an explicit V1 data limit.

### P3-2: Dependency audit is pending

Re-run `npm audit --audit-level=high` from a networked CI runner and review the lockfile result before release.

## Critical Manual Test Matrix

Run with separate VAT and non-VAT tenants, plus at least one product with stock and one service item.

1. Create quotation, save draft, reopen, edit, and send. Confirm numbering, totals, tax, and no stock deduction on quotation send.
2. Convert quotation to invoice once and twice concurrently. Confirm one invoice only, quotation converted once, and stock deducted once.
3. Create tax invoice/receipt. Confirm payment data, receipt labels, stock deduction, and PDF output.
4. Create billing note with multiple invoices. Confirm cross-BN locking, remove/re-add behavior, due date, overdue transition, and payment.
5. Record full, partial, WHT, cash, bank transfer, and cheque payments. Confirm receipt totals and outstanding balance.
6. Void invoice, receipt, billing note, delivery note, and credit note. Confirm status rules and stock restoration/idempotency.
7. Create delivery note from quotation with partial delivery, pending draft, over-delivery attempt, and remaining quantity.
8. Generate original and copy PDFs, download both orderings, ZIP mixed documents, and test long customer/item content.
9. Verify a second tenant cannot read or mutate the first tenant's customers, documents, files, stock, or reports.
10. Test Owner, Manager, Officer, and restricted permissions for save, send, payment, void, WHT, and settings actions.
11. Test mobile widths 375px and 414px, tablet 768px, and desktop 1280px across home, deals, documents, customers, reports, catalog, and settings.
12. Test network interruption during create, convert, send, payment, upload, and PDF generation. Confirm no silent partial state.
